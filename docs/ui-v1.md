# AgentBaton V1 低保真交互稿

## 1. 设计原则

- 先看 Agent 状态，再进入 Skill 细节。
- 所有会写入本机或远端的操作，先展示影响再要求确认。
- “当前状态”和“应用后状态”始终并列，避免用户把期望状态误认为已经生效。
- 状态文字与图标必须独立表达含义，颜色只是辅助。

## 4. Apply Plan：写入前的唯一确认点

```text
应用计划 / Codex                                      [取消]

将执行 6 项变更，完成后需手动重启 Codex。

新增 Installation      frontend-design → ~/.agents/skills/...
启用配置               internal-deploy
移除 Installation      video-cut
创建备份               ~/.codex/config.toml

风险提示
! internal-deploy 包含 1 个 shell 脚本；AgentBaton 不会执行它。

写前将重新验证 3 个目标文件未被外部修改。

[返回修改]                                      [确认并应用]
```

确认后显示逐 Agent 结果。多 Agent 批量应用时，每个 Agent 一张结果卡，可单独重试失败项。应用成功但需重启时，主按钮变为“我已重启，重新验证”。

## 5. Skill 库与纳管

```text
Skill 库
[全部 42] [已托管 15] [发现的 27]  搜索…  [筛选：来源 / Tag / 风险]

发现的 Skill / ui-polish
来源：~/.cursor/skills/ui-polish
原始描述：…
兼容：Cursor 兼容；Codex 未知
风险：包含 2 个脚本

[查看文件清单] [纳管到托管库]
```

点击“纳管”先进入预览：展示规范副本保存位置、来源类别、默认 `Local Only`、风险内容、初始分组为空。必须确认后才复制内容。

## 6. 分组与同步

分组详情显示成员、被哪些 Agent 启用、是否参与同步。打开“参与同步”时，页面计算并展示会写入远端的 Skill；`Local Only` 成员显示“不会同步”，并说明原因。

同步页将“检查到远端变更”“本地未同步”“冲突”分区显示。用户只能从变更摘要进入“立即同步”；内容冲突必须先选择本地、远端或保留两个 Skill。

## 7. 关键状态文案

| 状态 | 用户可见含义 |
|---|---|
| 状态一致 | 当前 Agent 已符合期望状态 |
| 待应用 | 用户已改期望状态，尚未修改 Agent |
| 待重启 | 配置已写入，用户需重启 Agent 后验证 |
| 安装漂移 | Agent 目录副本与托管库不同，需采纳或重新部署 |
| 只读 | 当前 Agent/平台没有安全写入方式 |
| 不兼容 | 已知无法被该 Agent 使用，不可应用 |
| 未知 | 缺少足够证据，用户可查看原因后选择尝试 |
