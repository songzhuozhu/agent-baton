# 开发路线

AgentBaton 的目标是让用户按场景组织 Skill，并可靠地为每个 Agent 选择和应用所需能力。当前为开发预览，功能状态以[验收审计](verification/v1-gap-audit.md)为准，已发布改动见[更新记录](../CHANGELOG.md)。

## 正式发布前：数据与状态一致性

| 优先事项 | 完成条件 |
| --- | --- |
| 撤销失败补偿 | 多文件撤销中途失败或数据库提交失败后，文件与元数据恢复一致；保留可重试备份；同一 Agent 操作串行化。 |
| 统一实时状态与应用计划 | 首页、Apply Plan 和重启后验证使用一致的实测结果；覆盖外部删除、内容变更和安装漂移。 |
| 托管内容与部署版本隔离 | 明确符号链接的生命周期，使库更新或删除不会在未经应用确认时改变 Agent 当前内容。 |
| 上游候选内容复查 | 确认时核验候选内容与预览一致，并清理过期暂存目录。 |
| 完整同步闭环 | 实测 GitHub 授权、私有仓库传输、冲突决议、双设备同步和新设备恢复。 |

## 使用体验

- 正确解析 YAML 多行描述，保留用户理解和搜索 Skill 所需的信息。
- 展示扫描失败的具体位置与处理方法，区分“没有发现”和“无法读取”。
- 为网络操作提供超时和重试，明确显示授权等待、拒绝与过期状态。
- 提供集中式设置、可重新打开的回收站和安装来源详情。
- 使用真实用户反馈完善发现、纳管、分组和应用流程，保持预览确认及 Local Only 边界。

## 分发与兼容性

- 在真实 macOS、Windows、Linux 桌面环境验证启动、纳管、部署与恢复。
- 为每个 Agent 记录实际版本、测试日期与加载结果；源码 CI 通过不等于 Agent 已加载成功。
- 验证后提供签名安装包、简短操作演示和可复制的示例 Skill。
- 建立版本升级与数据恢复说明，降低首次使用和回归测试成本。

## 贡献范围

优先接受可复现缺陷、兼容性证据、可访问性改进及有明确验收条件的小范围 PR。开发步骤见[贡献指南](../CONTRIBUTING.md)。

V1 聚焦 Skill 管理。Agent 编排、任务分发、第三方 Adapter 插件和商店不在当前版本范围内。
