# AgentBaton V1 需求文档

> **Slogan:** One baton. Every agent.\
> **文档状态:** 已确认\
> **产品边界:** 多 Agent 的本地 Skill 控制面

## 1. 产品概述

AgentBaton 是一款本地优先、跨平台的桌面应用。它统一发现用户电脑上多个 AI Agent 的 Skill，让用户将 Skill 纳入托管库、组织成可复用分组，并为不同 Agent 选择需要启用的 Skill 集合。

产品解决的核心问题是：Agent 安装大量与当前场景无关的 Skill 后，会增加上下文噪声、Token 消耗和管理成本。用户应能在工作开发、个人全栈开发、AI 剪辑等场景之间快速切换，只向各 Agent 暴露当前需要的 Skill。

V1 支持：

- Codex
- Claude Code
- Cursor
- Trae
- OpenCode

AgentBaton 桌面应用支持 macOS、Windows 和 Linux。各 Agent 的发现、部署与启停能力必须以[官方适配矩阵](./research/agent-adapter-compatibility-matrix.md)为准：当目标 Agent 没有该平台的官方客户端、官方路径或安全控制方式时，Adapter 必须降级为只读、警告或不兼容，不能伪称完整集成。

## 2. 产品目标

1. 汇总受支持 Agent 的用户级 Skill，形成统一、可理解的清单。
2. 通过 Skill Group 和按 Agent 的启用状态，降低场景切换成本。
3. 在不静默覆盖用户文件的前提下，将期望状态安全应用到各 Agent。
4. 保留第三方 Skill 的上游来源，并提供可审查的更新流程。
5. 通过用户自己的专用 GitHub 仓库，在多台设备间同步允许同步的 Skill 与管理状态。
6. 默认保护公司内部、私密或尚未明确允许同步的 Skill。
7. 以清晰的 Agent Adapter 边界支持未来新增 Agent，而不污染核心领域模型。

## 3. 核心用户场景

### 3.1 工作项目开发

用户在工作日前选择“公司开发”分组，将公司内部 Skill 应用到 Codex 或其他工作 Agent。该组中的私密 Skill 保持 `Local Only`，不会进入 GitHub 同步仓库。

### 3.2 个人全栈开发

用户在周末切换到“个人全栈”分组，为目标 Agent 启用前端设计、界面美化和全栈开发 Skill，同时停用只在公司项目中需要的 Skill。

### 3.3 AI 剪辑

用户选择“AI 剪辑”分组，将相关 Skill 应用到选定 Agent。多个 Agent 可以独立启用同一分组，也可以同时启用多个分组。

### 3.4 新设备恢复

用户在新电脑安装 AgentBaton，通过 GitHub 授权连接已有同步仓库。应用先恢复 Skill、分组和各 Agent 的期望状态，再扫描本机 Agent 并生成应用计划；用户确认后才安装或启用 Skill。

## 4. 功能需求

### FR-01 Agent 与 Skill 发现

- 自动检测五种受支持 Agent 是否安装。
- 扫描各 Agent 已知的用户级 Skill 位置。
- 允许用户添加自定义扫描目录和项目根目录。
- 不执行整盘扫描。
- Agent 内置且只读的系统 Skill 只作为系统能力处理，不进入托管范围。
- 项目级和自定义目录中的 Skill 可以被发现、查看和纳管，但 V1 只向用户级作用域写入。
- 扫描过程不得执行 Skill 中的任何内容。

### FR-02 Skill 身份与纳管

- 区分逻辑 `Skill` 与实际部署的 `Skill Installation`。
- 发现的 Skill 默认只读，不自动复制、修改或上传。
- 用户明确纳管后，AgentBaton 在托管库创建唯一规范副本。
- Skill 使用稳定 UUID 标识；名称或内容相同不能自动判定为同一 Skill。
- 对疑似重复 Skill 提供提示，由用户决定是否合并。
- 同一符号链接的规范目标可识别为同一个 Installation 来源。

### FR-03 Skill 信息与筛选

- 展示名称、原始描述、用户描述、来源、上游状态、Tag、同步策略、兼容状态和安装位置。
- 原始描述读取自 `SKILL.md`，只读展示。
- 用户描述只保存在 AgentBaton 元数据中，不写回 Skill，也不影响 Agent 的触发逻辑。
- 用户描述存在时卡片优先展示用户描述，详情页同时展示两种描述。
- Skill 可以拥有多个自由 Tag；Tag 只用于搜索、筛选和展示。

### FR-04 Skill Group

- 用户可以创建、重命名和删除 Skill Group。
- Skill 与 Skill Group 是多对多关系。
- Skill Group 是全局逻辑集合，不对应文件夹，也不复制 Skill 内容。
- 一个 Skill Group 可以被多个 Agent 独立启用。
- 一个 Agent 可以同时启用多个 Skill Group。
- 删除或修改分组前展示受影响的 Agent 和 Skill。

### FR-05 按 Agent 管理期望状态

- 每个 Agent 独立记录已启用 Skill Group。
- 支持把一个或多个 Skill Group 批量分配给多个 Agent。
- 支持单 Skill 三态覆盖：跟随分组、强制启用、强制禁用。
- 有效 Skill 集合按以下规则计算：已启用分组的并集，加上强制启用，再排除强制禁用。
- 多组共享同一 Skill 时按逻辑身份去重；关闭一个分组不得移除仍被其他启用分组引用的 Skill。

### FR-06 状态、数量与界面反馈

- 首页采用 Agent-first 信息架构，首先展示 Agent 卡片和状态。
- Agent 详情页展示已启用分组、可用分组、有效 Skill 集合、单 Skill 覆盖以及应用入口。
- 当前启用数按观测状态中的逻辑 Skill 去重计算，不按 Installation 数量累计。
- 状态一致时展示当前启用数。
- 状态不一致时同时展示当前值和应用后值，例如 `12 → 18`。
- 配置已写入但目标 Agent 尚未重新加载时，展示“待重启”。
- AgentBaton 不自动关闭或重启 Agent；用户手动重启后，应用重新验证状态。

### FR-07 兼容性与 Agent Adapter

- 每种 Agent 通过独立 Adapter 实现检测、扫描、兼容性验证、计划、部署和验证。
- Agent Adapter 的平台能力由官方兼容矩阵约束；TRAE 在 Linux 上仅显示“无官方支持证据 / 不提供集成写入”，直到取得新的官方依据和真实验证。
- 兼容状态包括：兼容、兼容但有警告、不兼容、未知。
- 明确不兼容时阻止应用并展示原因。
- 状态未知时，允许用户确认后尝试部署并验证结果。
- Adapter 可以生成外围配置，但不得静默改写 Skill 指令正文。
- V1 的五个 Adapter 内置发布，不加载第三方 Adapter 插件。

### FR-08 应用、部署与回滚

- 任何本机写入前必须生成可预览的 Apply Plan。
- 计划展示新增、移除、启用、禁用、配置修改、风险提示和是否需要重启。
- 用户确认后才执行写入。
- Adapter 优先使用 Agent 原生启停机制；其次使用符号链接或 Windows Junction；必要时使用受控复制。
- 每个 Installation 记录部署方式和内容哈希。
- 写入前重新校验目标文件；目标已变化时停止对应 Agent 的应用并重新规划。
- 修改前创建本机备份。
- 单个 Agent 的应用是原子事务，失败时回滚该 Agent。
- 多 Agent 批量应用可以部分成功，必须逐项展示结果并允许只重试失败项。
- 保留应用记录；备份仍有效时支持撤销最近一次对应应用。
- 检测到安装副本与规范副本不一致时标记安装漂移，由用户选择采纳外部修改或重新部署。

### FR-09 来源与上游更新

- Skill 分为本地来源和上游来源。
- 上游来源保存仓库地址、仓库内相对路径、最后同步 Commit 和内容哈希。
- 应用启动时可以检查更新；自动检查间隔不得短于 24 小时，并支持手动批量检查。
- 检查更新只读取状态，不修改托管库或 Agent。
- 用户请求更新后，候选内容先进入隔离暂存区并展示文件差异、版本和受影响 Agent。
- 用户确认后才更新托管库，并生成新的 Apply Plan，不自动部署。
- 本地内容相对上游基线发生修改时标记为已分叉，阻止直接更新。
- 用户可选择保留本地版本，或在创建备份后放弃本地修改并更新。
- 上游仓库或原路径不可用时保留当前版本并显示状态。

### FR-10 同步策略与分组选择

- 每个托管 Skill 具有固定同步策略：`Local Only` 或 `Sync Allowed`。
- 新纳管 Skill 默认为 `Local Only`。
- `Local Only` 优先于所有分组设置，任何情况下都不得写入同步仓库。
- 每个 Skill Group 具有持久的“参与同步”开关。
- 只有同时满足“所属分组参与同步”和“Skill 为 Sync Allowed”的内容才能进入同步快照。
- Tag 不参与同步授权判断。
- 将已同步 Skill 改为 `Local Only` 时，展示影响并在确认后从当前和未来同步快照移除。
- V1 不自动清理 Git 历史；界面必须提示历史中可能仍保留旧内容。

### FR-11 GitHub 同步

- V1 同一时间连接一个 AgentBaton 专用 GitHub 仓库，不支持把业务代码仓库作为同步仓库。
- 默认要求仓库为用户控制的私有仓库。
- 通过 AgentBaton GitHub App 和 Device Flow 授权，不提供经典 PAT 文本输入框。
- 凭据仅保存在操作系统安全存储：macOS Keychain、Windows Credential Manager、Linux Secret Service。
- 应用启动或恢复前台时可以自动检查远端状态，但不得后台自动提交或推送。
- 用户点击“立即同步”后先查看本地、远端和删除变更摘要，再确认提交与推送。
- 不同字段的结构化修改可以自动合并，但必须展示结果。
- 同一字段冲突由用户选择本地或远端。
- Skill 内容双方都修改时不得静默合并；用户可以选择本地、远端或保留为两个独立 Skill。
- 冲突全部解决前不得推送。
- 拉取到新设备的状态只形成期望状态和 Apply Plan，不自动安装。

### FR-12 删除与卸载

- 移出分组只修改成员关系。
- 对 Agent 禁用只修改该 Agent 的期望状态。
- 从 Agent 卸载只移除该 Agent 的 Installation；若期望状态仍要求启用，必须同时调整期望状态。
- 删除托管 Skill 会从所有分组、Agent 期望状态和同步快照移除，执行前展示影响范围并二次确认。
- 删除项进入 AgentBaton 回收站，默认保留 30 天。
- 使用删除墓碑将删除意图传播到其他设备，防止旧副本重新创建已删除 Skill。
- AgentBaton 永远不直接删除发现但未托管的外部原始 Skill。

### FR-13 风险提示

- Skill 默认视为未审查，不展示“安全”或“已验证”等认证性标签。
- 扫描、纳管、同步和更新过程不得执行 Skill 内容。
- 拒绝目录穿越和指向托管范围外的符号链接。
- 检测脚本、可执行文件、二进制文件和符号链接，并显示风险内容清单。
- 首次纳管或更新包含风险内容的 Skill 时要求用户显式确认。
- V1 不承诺恶意代码检测能力。

### FR-14 设置与诊断

- 管理自定义扫描目录、GitHub 连接、同步仓库和本机存储位置。
- 展示五种 Agent 的检测结果、Adapter 状态和已知路径。
- 错误日志仅保存在本机并对凭据脱敏。
- 用户可以手动生成诊断包；生成前展示文件清单。
- 诊断包默认排除 Skill 正文、凭据和绝对路径，且不自动上传。

## 5. 数据与同步边界

### 5.1 当前设备保存

- GitHub 凭据
- Agent 实际路径和自定义扫描目录
- Skill Installation
- 观测状态、缓存、日志、临时备份和应用记录
- `Local Only` Skill 的内容与仅本机元数据

### 5.2 允许跨设备同步

- 满足同步条件的 Skill 内容
- Skill 原始元数据之外的用户描述与 Tag
- 上游引用和同步基线
- Skill Group、成员关系和参与同步设置
- 各 Agent 的已启用分组与单 Skill 覆盖
- 删除墓碑和格式版本

### 5.3 存储结构

- SQLite 本地状态库保存设备状态，并使用显式迁移版本。
- 普通目录形式的托管库保存规范 Skill 内容。
- Git 仓库保存按实体拆分的确定性 JSON 和原始 Skill 文件结构。
- 所有可移植实体使用稳定 UUID，JSON 包含 `schemaVersion`。
- SQLite、凭据、设备路径、缓存和扫描结果不进入 Git。

## 6. 交互与视觉要求

- 图形界面应简洁、克制，核心流程围绕“选择 Agent—选择分组—预览—应用”。
- 首页不以文件目录为中心，而以 Agent 当前状态和待处理事项为中心。
- 危险操作、远端写入和本机配置修改必须可预览、可取消。
- 空状态应直接引导用户完成扫描、纳管、创建分组和首次应用。
- 支持浅色、深色和跟随系统主题。
- 状态不能只依赖颜色表达；关键操作支持键盘导航并提供可读标签。
- 三个平台使用一致的信息架构，同时遵循各平台基本窗口和快捷键习惯。

## 7. 非功能要求

### 7.1 跨平台

- macOS、Windows、Linux 使用同一核心领域逻辑，并均可构建和运行 AgentBaton。
- 五种 Agent 的平台集成能力不假定相同，必须按官方兼容矩阵进行检测和降级；缺少官方 Agent 支持不构成 AgentBaton 桌面应用跨平台构建失败。
- 文件路径、权限、安全存储、符号链接和 Junction 差异封装在平台层与 Adapter 中。
- 不以管理员权限作为正常使用前提。

### 7.2 安全与隐私

- 本地优先，不要求 AgentBaton 产品账号。
- 除 GitHub 同步、上游检查和产品必要版本检查外，不发送用户数据。
- V1 不包含产品分析、行为埋点或远程日志。
- 未来遥测必须由用户明确选择加入。
- 所有写入遵循预览、确认、备份、校验和验证流程。

### 7.3 可靠性

- 应用异常退出不得留下无法识别的半完成单 Agent 状态。
- Git 冲突、网络失败和 Agent 配置变化不得造成静默数据覆盖。
- 数据格式必须可迁移；读取更高版本格式时不得冒险降级写入。
- 核心状态变更应具备确定性测试，五个 Adapter 应具备契约测试。

### 7.4 可扩展性

- Skill、Installation、Group、Desired State、Observed State 和 Adapter 保持独立边界。
- 新增 Agent 不要求修改分组、同步和 Skill 身份算法。
- V1 Adapter 接口是内部接口，不承诺第三方兼容性。
- 同步格式通过 `schemaVersion` 演进，迁移必须保持向前升级路径。

## 8. V1 非目标

- Agent 之间的任务分发、消息传递和工作流编排
- 自动启动、关闭或重启 Agent
- 项目级 Skill 的写入和按项目自动切换
- Skill 编辑器、Skill 市场和在线审核体系
- 团队空间、组织权限、审批与协作
- 第三方 Adapter 插件运行时
- 后台自动同步、自动上游更新和静默部署
- 恶意代码安全认证
- Git 历史重写或敏感信息自动清除
- AgentBaton 公共云账户与托管服务

## 9. V1 验收主链路

V1 达到可交付状态时，至少应通过以下端到端场景：

1. 在三个操作系统上构建并运行 AgentBaton；检测已安装且受官方矩阵支持的 Agent，并扫描其用户级 Skill。对无官方平台支持或能力待验证的 Agent，准确显示只读或不兼容状态。
2. 将发现的本地 Skill 和 Git 上游 Skill 纳入托管库，保留正确来源。
3. 让同一个 Skill 同时属于多个分组，并验证切换分组不会产生重复部署或误删共享 Skill。
4. 为多个 Agent 选择不同分组，正确计算单 Skill 覆盖和应用前后数量。
5. 预览并应用计划；目标文件被并发修改时安全中止；单 Agent 失败时成功回滚。
6. 对需要重启的 Agent 显示待重启，并在用户重启后验证实际状态。
7. 证明 `Local Only` Skill 无法因分组设置或误操作进入 Git 仓库。
8. 在两台设备间完成手动同步，正确处理结构化字段冲突和 Skill 内容冲突。
9. 在新设备拉取期望状态而不自动安装，确认 Apply Plan 后再部署。
10. 检查并预览上游更新；已分叉 Skill 不被静默覆盖。
11. 删除托管 Skill 后可在 30 天内恢复，并通过墓碑阻止另一台设备恢复旧副本。
12. 生成不包含凭据、Skill 正文和绝对路径的默认诊断包。

## 10. 开发启动条件

本需求文档已满足产品范围冻结条件。进入实现前仍需产出：

1. 技术选型与总体架构设计。
2. 五个 Agent 的路径、配置能力和版本兼容矩阵。
3. 同步仓库格式规范与迁移策略。
4. 核心页面低保真交互稿和视觉方向。
5. 按风险排序的开发里程碑与测试策略。

以上产物用于减少返工，不改变本文已经确认的 V1 产品边界；若发现事实与假设不一致，应新增架构决策并更新本文。
